采样回答

候选生成 投机解码先让一个便宜的草稿模型（分布 q）自回归地连续猜出若干假设 token，作为目标模型后续验证的“假设前缀”。这一阶段不改变目标模型，只是提供并行性的来源，草稿质量只影响接受率、不影响最终分布是否正确。 [1]

并行验证 草稿把候选位置补成一条已知序列后，目标大模型（分布 p）用它做一次“块前向”，在 causal mask 约束下同时算出每个候选位置的目标分布，从而用一次权重读取服务多个位置，而不是像普通解码那样每步只算一个新 token。 [2]

加速边界 投机解码本质上针对 Decode 阶段的访存瓶颈，通过减少目标模型串行步数与权重搬运来压低头字延迟，但它不减少总 FLOPs、也不解决 Prefill；只在低并发、长输出、访存受限时收益最明显，一旦大 batch/高并发把 GPU 算力吃满，收益会衰减甚至变慢。 [3]

核验提示 回答提到“头字延迟”。第 241 行写的是解码阶段每个输出 token 的耗时（TPOT/ITL），并说明 Prefill 不会明显加速。 [3]

    自己的密钥，自己的选择

    BYOK · 密钥保存在服务端。浏览器只显示是否已配置，服务端向所选供应商发起请求时才附上密钥。

    DeepSeek 官方

    api.deepseek.com/anthropic/v1/messages

    原生 Messages 接口。每个任务沿用启动时选择的模型和凭据。

    阿里云百炼

    dashscope.aliyuncs.com/apps/anthropic/v1/messages

    Qwen 3.8 Max 可结合图片和 PDF 回答，原生思考等级在配置页选择。

    Kimi

    api.moonshot.cn/anthropic/v1/messages

    使用 Kimi 的 Messages 接口，在配置页核验凭据与模型 ID。

    自定义 Anthropic 端点

    models.example.com/v1/messages

    示意地址。填写你的兼容端点、认证方式与模型 ID，再运行连接检查。

    Tavily 联网

    api.tavily.com/search

    单独配置搜索密钥。开启联网补充时发送查询，个人学习回顾只读所选知识库。

    本地 Whisper + FFmpeg

    FFmpeg → faster-whisper

    提取关键帧并在本机转写。首次使用需准备语音模型，提取内容可随任务交给所选模型。

    外部模型会收到问题、附件和选中的笔记片段；远程 Embedding 服务会收到参与索引的文本。不开启模型也可使用本机关键词检索。 查看数据流 ↗

    适合怎样的书房？

    设计目标

    • 单管理员，在自己掌握的设备上自托管。
    • 原文证据优先，写入前审核草稿。
    • BYOK 接入模型，多知识库独立运行。

    明确非目标

    • 多租户账号和细粒度团队权限。
    • 跨库联合检索或合并多个库的上下文。
    • 托管 SaaS 或代管你的 API 账单。
