# Personal learning reviews

Requests such as “总结最近一个月的学习重点” use a dedicated local review flow in both Normal and Deep modes. An omitted “我” does not require a subject clarification. “所有”, “全部”, and “所有的” continue the original question and the time window fixed at its first turn, including after restoring or forking a conversation. Public questions about machine-learning research progress retain the ordinary research flow.

The configured timezone defines calendar boundaries. “最近一个月” starts at local midnight one calendar month before the first request and ends at that request. “上个月” means the preceding calendar month. Personal reviews skip Web Search even if the conversation's Web preference is enabled; that preference remains available for unrelated subsequent questions.

## Evidence and coverage

The server enumerates the current knowledge-base snapshot rather than taking the first topK search hits. It identifies dated diary entries, plans, weekly date headings and date-table rows. Long records are split into continuous pieces. Explicit event dates override enclosing record dates. A weekly range straddling a boundary cannot prove that an undated event happened inside the requested period.

Month/day records require an explicit year or, for date-record locations only, a unique year in the requested window. The answer reports use of this latter inference. Ordinary undated learning notes do not acquire a date from the query or from their file modification time.

Ordinary reference notes cannot independently establish personal activity, even when their filename or title contains a date. Diary and plan records, or explicitly identified learning/revision/practice/reading logs, provide the primary event anchor. A copied author’s experience or a definition remains reference material.

Each accepted event retains its original lines, exact evidence quote, date and status: completed, in progress, planned or unconfirmed. Incorrect model-supplied line numbers can be corrected only when the verbatim quote has one unique occurrence in the supplied segment; validation still examines the original surrounding line and task checkbox. Unchecked goals are plans. Absence of a deliverable is not evidence of non-completion. Supporting notes can explain an already established event; they must cite that event and cannot change its date or completion status. Thus a July note may explain a September revision only when September records actually establish that revision.

Coverage reports distinguish complete processing of a file's in-window portions, partial processing, failures and budget omissions. Opening a file or returning a search hit is not a full model read. Files changed since the leased index snapshot are rejected before their text enters evidence. Rejected facts and uncertain temporal attribution are reported separately.

The source-text ceiling is 24,000 characters per batch, additionally limited by `RAG_MAX_CONTEXT_CHARS`. Actual dated-record batches use at most `min(RAG_MAX_CONTEXT_CHARS, 2,400)` characters because date records contain many separate facts. Supplementary batches use at most `min(RAG_MAX_CONTEXT_CHARS, 8,000)` characters, including the repeated original-event evidence. Both phases share a limit of 12 extraction calls and 240,000 source characters; these are ceilings, not a promise that a task will consume the full budget.

Extraction uses the selected model at low effort, a 180-second timeout and up to 12,000 output tokens for structured facts. At most two extraction calls run concurrently. An otherwise complete JSON object with unescaped interior double quotes may be corrected only by inserting quote-escape backslashes: a character-by-character guard rejects every other repair, including truncation or missing delimiters. Facts still pass the same evidence, date and status checks. Remaining malformed JSON, invalid top-level structure, transient network failures, timeouts or truncated output receive at most one retry of the original batch, sharing both call and character budgets. Valid JSON with unverified evidence is rejected without retrying to obtain different facts. Exact quotations with incorrect line numbers can be relocated only when they appear uniquely in the same processed segment. Dated records receive priority over up to eight supplementary topic searches, 24 supporting notes and one layer of references. Supplementary batches are planned across note boundaries before execution so two short notes can run concurrently; each batch retains its own verified parent event, dates and status. Remaining task time must reserve the final answer before any additional extraction begins. The final ID grouping uses the selected model at low effort with a 90-second, 2,500-token ceiling; if grouping fails, the server groups by the verified topics. The server renders every validated fact and citation, so grouping cannot omit evidence. A budget limit produces an explicit incomplete-coverage statement.

## Deployment and acceptance

Update frontend and backend together and restart the running backend after changing source. Use the authenticated `/api/knowledge/status` response to verify the current build, selected knowledge base and index. For independent working copies, follow [the manual replica procedure](sync.md#manual-working-copy-beside-a-fixed-benchmark); copying files alone does not update an already active embedding slot.

The regression suite uses synthetic records and a fixed clock, including the exact three-turn sequence, old notes revisited inside the window, out-of-window events, unchecked plans, cross-year dates, long lines, changing files and snapshot isolation. Keep private evaluation copies and model transcripts outside the repository. Compare implementations using the same frozen files and reference time; retain the previous benchmark when refreshing operational data.
