# 文件清单与最后修改时间查询

原版和 Second Mind 使用相同的只读枚举实现。文件清单不调用模型或向量服务，也不读取笔记正文。

## 使用

在知识问答中输入：

- `列出全部笔记`：包含根目录和各级子目录中的 `.md`、`.MD`。
- `最近新写了哪些笔记`：按最近一个自然月的最后修改时间查询，不能证明首次创建时间。
- `列出 2026-08-16 至 2026-09-16 修改了哪些文件`：结束日期覆盖完整一天。
- `列出 2026-08-16 00:00:00 至 2026-09-16 09:41:36 修改了哪些笔记`：保留具体时刻，终点不包含。
- `列出全部文件，包括附件`：包含普通附件文件。

卡片显示北京时间、实际范围、开始/结束时间、已发现/已处理路径数、匹配数、排除和缺口。每页 50 条，翻页读取同一份已保存结果。范围选择器可切换 Markdown / 全部文件后重新扫描。

“最近”采用北京时间当前时刻向前一个日历月，同日同刻，月末不足则取上月最后一天。相关清单追问沿用当前对话已有范围；明确日期、本月、上月、今天、昨天、自然周、最近 N 天优先。全部时间可以通过“列出全部笔记”或 API `allTime: true` 指定。

“哪些笔记提到了 CUDA”“解释这些笔记的正文”等内容请求仍走普通问答。清单之后的内容问答携带清单标识和时间口径，清单卡片仍保留。

## 接口

沿用站点登录、请求来源检查和写请求防护头。Second Mind 可在 URL / 请求体中指定 `knowledgeBaseId`；省略时使用默认库。

```http
POST /api/knowledge/inventories
Content-Type: application/json

{"scope":"markdown","start":"2026-08-16","end":"2026-09-16","timeZone":"Asia/Shanghai"}
```

返回 `inventoryId`、`taskId` 和 `conversationId`。可指定已有 `conversationId`；不传则创建清单对话。根目录由服务端选择，不能由请求指定。

```http
GET /api/knowledge/inventories/:id
GET /api/knowledge/inventories/:id?cursor=50
POST /api/knowledge/inventories/:id/cancel
```

可附加 `conversationId` 进行一致性检查；传入错误对话返回 404。跨用户、跨库或已删除所属对话的清单返回 404。分页游标是本次冻结结果的 50 条偏移，只能使用返回的 `nextCursor`。

也可用原任务入口 `POST /api/knowledge/tasks` 提交自然语言问题或显式 `inventory` 对象。复用任务事件流，其中 `inventory` 事件携带真实扫描进度；复用任务取消入口。

结果 `matched` 在枚举/复查阶段为 `null`，此时不编造总数或呈现最终分页。`discovered` / `processed` 统计已发现/已处理的路径，包括目录和排除项，不是正文阅读数。

## 完整性与存储

- 先枚举，再按 `[start, end)` 筛选；修改时间降序，同时间按相对路径排序。
- 跳过隐藏路径、符号链接和非普通文件，逐项给出原因。隐藏目录记一个被排除的子树，不读取其内部文件。
- 子目录访问失败会保留缺口；根目录访问失败为 `failed`。
- Linux 使用目录文件描述符和 `O_NOFOLLOW` 防止链接替换导致越界；元数据复查比较文件属性及目录成员/类型。
- 扫描期间发现变化或访问错误为 `incomplete`；只有没有缺口的完成结果才显示“文件清单扫描完成”。扫描是期间观测，无法证明文件系统原子快照，也不能检测两次观测之间完全恢复的瞬时变化。
- 状态文件保存在当前知识库运行态的会话文件旁 `file-inventories/`，不写入知识库。写入采用临时文件后重命名，目录 0700、文件 0600。
- 服务启动把遗留的 queued/scanning/verifying 清单标为 `interrupted`。完成清单重启后保持不变。删除/清空所属对话时同步清理清单。
- 不修改笔记、内容或时间属性，不重建索引，不调整普通问答预算。未增加全文核查、阅读进度或断点续读。

## 验证

`test/original/knowledge-inventory.test.mjs` 验证枚举、冻结分页、日期、取消/中断、变化检测、用户隔离及笔记不变性。`test/knowledge-inventory-api.test.mjs` 验证实际 API、Chrome、模型禁用、多知识库隔离以及清单后续聊。测试模型调用使用隔离的模拟供应商。

原版对应 `test/knowledge-inventory.test.mjs`，另包含原版 Worker 接口与认证测试。实际站点验收和私有回退位置记录在本机验收报告，不包含在此公开文档中。
