多知识库

一个服务，多个彼此隔离的知识上下文

从允许的宿主机父目录发现一个根 Vault 或其直接子 Vault。每个注册目录都必须是含实际、非符号链接 .obsidian 目录的 Vault 根。每个知识库拥有独立的索引命名空间、任务上下文和写入边界。

稳定 ID 永久绑定首次规范化的 Vault 路径，即使删除注册项或重启也不会释放。另一套 Vault 必须使用新 ID，包括宿主机在相同路径替换内容的情况。

当前限制：一次任务只绑定一个知识库，不提供跨库联合检索，也不是任意文件浏览器。

允许的挂载边界

/vaults ↓
  1. 发现根 Vault 或直接子 Vault只在允许根目录内
  2. 注册稳定的知识库标识拒绝路径逃逸和重叠
  3. 绑定会话与任务选择一次只处理一个知识库
  4. 隔离索引与写入范围不会默默混合语料

BYOK 与隐私

凭据留在服务端，数据去向由配置决定

模型、网页搜索与嵌入凭据分别配置。安装不会触发付费 API 调用，没有模型凭据时仍可登录并使用本地 BM25 检索。

  • 浏览器不会读回已保存的密钥
  • 静态站点没有统计脚本、Cookie 或远程字体
  • Vault 文件与索引保存在你管理的主机和 Docker 卷中

自托管不代表所有操作始终仅在本地。当你启用外部模型、嵌入、网页搜索或页面读取时，所选文本、查询或公开 URL 会发往对应服务。要求内容绝不出站时，只从本机浏览器访问，只使用在同一主机运行的兼容 Provider，禁用联网与远端同步，并把备份留在受控本地存储。部署前请检查数据流说明与提供商政策。

三平台快速安装

准备 Docker，选择一个知识库目录

安装器只询问 Vault 或知识库父目录、管理员密码和端口。运行逻辑在 Node 容器中执行，宿主机不需要安装 Node.js。

前置条件：Git；Linux 使用常规 rootful Docker Engine 与 Compose v2，macOS 和 Windows 使用 Docker Desktop。rootless Docker 或 SELinux enforcing 主机需要管理员另行设计 UID、卷权限和 bind-mount relabel；安装器不会自动修改这些边界。

Docker Engine + Compose v2

git clone https://github.com/kygoyuan2004/Second-Mind.git
cd Second-Mind
./install.sh

Docker Desktop

git clone https://github.com/kygoyuan2004/Second-Mind.git
cd Second-Mind
./install.sh

PowerShell + Docker Desktop

git clone https://github.com/kygoyuan2004/Second-Mind.git
cd Second-Mind
powershell -ExecutionPolicy Bypass -File .\install.ps1
安装后使用同一个入口： doctorstatuslogsupdatebackup

运维边界：backup 是含凭据的实时副本，不是应用与同步器的原子快照，也不自动收集独立同步器状态。恢复需要人工验证；update 没有自动镜像回滚；当前也没有永久卸载命令。停止服务时只针对精确实例执行 docker compose down，不要带 --volumes。详见 部署文档。

当前边界

先把适用范围说清楚

适合
一个可信管理员在自己控制的设备或私有网络中管理个人或小团队知识库。
尚不提供
多租户账号体系、细粒度团队权限、跨知识库联合检索和托管云服务。
网络责任
默认保持本机或私有网络访问。如需公网入口，请自行配置 TLS、访问控制和备份。
PDF 读取
标准镜像不包含 bwrap 和 pdftotext，因此网页 PDF 读取默认不可用，也不会回退到无 sandbox 解析。确认后的 PDF 附件持久化不等于 PDF 内容理解。
平台集成
不安装 Windows Service 或 macOS LaunchDaemon，也不集成 Credential Manager 或 Keychain。
